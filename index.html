01 — pace-aware finance app

Ledger — Savings Tracker

A React app that tracks a savings goal week by week and tells you whether you’re actually on pace to hit your deadline — not just ahead or behind, but the exact weekly rate you’d need starting today, compared against what you’ve committed to save.

  • Builds a linear benchmark schedule from starting savings to target, then separately computes the real required weekly rate from today’s progress
  • Line chart of expected vs. actual savings over time (Recharts), backed by a timestamped history log of every deposit
  • Deposit-based logging updates current savings, percent complete, ahead/behind status, and projected total in one atomic state update
  • Guided setup with editable goal parameters — schedule, chart, and stats all recalculate live, including edge cases like a shortened deadline
React Vite Recharts CSS

What I learned

  • Why a simple ahead/behind indicator isn’t enough — computing a separate required weekly rate gives a more honest signal than a progress bar
  • How to keep derived state (schedule, chart data, stats) in sync by recomputing it all from the same source of truth instead of updating each piece independently
  • How to unit test pure calculation logic with node --test, separate from the UI, to catch edge cases like a shortened deadline after check-ins already exist

02 — roguelike engine

Emberdeep

A browser-based roguelike dungeon crawler in vanilla JavaScript and HTML5 Canvas. Every level is procedurally generated, then validated with the same BFS used to drive enemy pathfinding.

JavaScript HTML5 Canvas Node.js

What I learned

  • How to reuse one graph-search algorithm (BFS) for two different jobs — pathfinding and level validation
  • Why generated content needs a fallback path instead of trying to patch an unsolvable layout
  • How to test game logic without a browser, using a headless Node.js harness for hundreds of simulated runs
Live Demo Source

03 — timing engine

Rubik’s Cube Speed Timer

A competition-inspired speedcubing timer with millisecond-accurate timing, a WCA-style scramble generator, and Ao5 / Ao12 session statistics with proper DNF handling.

JavaScript HTML CSS

What I learned

  • Why setTimeout isn’t accurate enough for millisecond timing, and how performance.now() and requestAnimationFrame fix that
  • How to design a small state machine (idle → ready → timing → stopped) so a timer can’t get stuck in an invalid state
  • How to handle edge cases like DNFs and small sample sizes without breaking the Ao5 / Ao12 averages
Live Demo Source

04 — input & state

Reaction Time Game

An event-driven browser game that measures reaction time across randomized intervals and difficulty levels, with persistent high scores saved locally.

JavaScript HTML CSS

What I learned

  • How to structure game state around events instead of a single update loop, since reaction time only cares about a few precise moments
  • How to save and reload high scores with localStorage, including handling missing or corrupted data gracefully
  • How randomizing wait times prevents players from just timing the interval instead of reacting to it
